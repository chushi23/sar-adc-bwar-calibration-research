16-bit SAR ADC CDAC 校准架构研究 — 三项目代码解读

本目录包含三个相互承接的 MATLAB 工程。它们研究同一件事：在单位电容随机失配下， 四种 16-bit SAR ADC 的电容 DAC（CDAC）架构能否靠前台数字校准（CAL0/CAL1/CAL2）达到 16-bit 规格 （DNL<1 LSB、INL<4 LSB、零缺码、单调）。三个项目是同一研究的三个阶段，后一阶段通过 addpath 只读复用前一阶段的引擎代码，逐步收敛到最终可版图实现的方案。

三项目一句话定位
目录阶段作者做什么关键产出
calibration_architecture_study Phase 0–3（地基）Codex 建立四架构仿真引擎 + 原始架构基准 校准引擎、CAL0 静态回归、四架构 MC 基准
calibration_architecture_study_p4_8 Phase 4–8（选型）ZCode 加冗余变体 + CAL2 有限字长 + 动态敏感性 + 选型 推荐 BWAR-final
bwar_implementation_refinement Phase A/B/C（精炼）ZCode 把非整数桥 1.949Cu 收敛到整数桥（Cb=2Cu）可实现方案 整数桥可行候选 + CAL2/编码/offset 行为模型

一、三项目演进链与代码复用关系

三个项目不是互相独立的代码库，而是一条继承链。关键在于：每一阶段都不修改前一阶段的任何文件， 而是用 addpath(genpath(...)) 把前一阶段的 matlab/ 加进 MATLAB 路径，直接调用其已验证的函数。

复用地基的工程纪律（从 config 文件可见）： config_p48.m 第 5–7 行把 calibration_architecture_study/matlab 加进路径； config_impl.m 第 8–10 行把 两个前序目录都加进来。三套配置都显式声明： “Reuses … read-only via addpath; never writes there.” 所有新产物只写进自己的 raw/csv/figures/reports 目录。

二、共享核心引擎（Phase 0–3）的实现

这是整个研究的“物理内核”。它把一套 ADC CDAC 抽象成电容网络 + 比较器判决树，用精确区间传播算出 每个输入电压对应的输出码，再统计 DNL/INL/缺码/单调。下面逐文件说明它如何实现。

2.1 电容网络 → 节点方程（network_weights.m）

所有的电容被分到若干节点（seg 数组标定段号），节点之间用桥电容耦合。求解的是节点电压 g：

% network_weights(a,cap,bridge)  值单位为 Cu
nnode = max(a.seg);
totals = accumarray(a.seg(:), cap(:), [nnode 1]);   % 每段物理电容总和
C = diag(totals);                                    % 节点导纳对角
for j = 1:numel(bridge)
    v = zeros(nnode,1); v(j)=1; v(j+1)=-1;
    C = C + bridge(j)*(v*v');                        % 桥电容加非对角耦合
end
e = zeros(nnode,1); e(1) = 1;
g = C \ e;                                           % 解 C·g = e_TOP
w = reshape(cap,1,[]) .* reshape(g(a.seg),1,[]);     % 每个电容的有效权重 = cap × 所处节点 g

这正是拉普拉斯节点方程：把 TOP 节点驱动到单位电压，解出的各节点电压 g 乘以各电容自身容值， 就得到每个电容在二进制权重意义上的“有效权重”。桥电容把相邻节点耦合起来（BWA 的 8+8 桥、Current 的两级桥）， 是实现分段衰减的关键。这一步是整个仿真的物理基础，p4_8 与 bwar 都直接复用它。

四个架构靠 cap（电容数组）、seg（段归属）、bridge（桥电容）、convention（判决约定）来区分：

2.3 失配建模与“每颗芯片”（realize_architecture.m）

单位电容失配遵循标准 √(面积) 律：电容越大、相对波动越小。

cap = a.cap + cfg.sigma*sqrt(a.cap).*randn(st,2,numel(a.cap));
bridge = a.bridge + cfg.sigma*sqrt(a.bridge).*randn(st,2,numel(a.bridge));

其中 cfg.sigma = sqrt(K_fF/Cu_fF) = sqrt(0.0399818695/150) ≈ 1.6326% 是单位失配 σ_u。 每颗芯片用可复现随机流：seed = seedMC + 100000·archIndex + chip（mt19937ar）， P/N 两侧独立抽取。P/N 侧权重取平均得到该芯片的“真实权重”，再经 network_weights 解算。 chip=0 表示无失配的名义（nominal）芯片。

2.4 精确判决树 / 传输函数（transfer_tree.m vs sar_convert.m）

这是把“模拟 SAR 过程”转成“数字区间集合”的核心。不再逐点扫描输入电压，而是从根区间出发， 每级判决把当前存活区间一分为二，并记录每个叶子区间对应的决策比特与最终码。这样做精确且无网格误差。

% transfer_tree：区间精确传播
for k = 1:a.decisions
    if monotonic
        threshold = state + real.weights(j);   % 单调约定：d=1 推进，d=0 保持
        statePair = [state; threshold];
    else % fullstep (Current)
        threshold = state;
        statePair = [state - w; state + w];      % 全步约定：d=1 +w，d=0 -w
    end
    loPair = [lo; max(lo,threshold)]; hiPair = [min(hi,threshold); hi];
    valid  = hi - lo > widthTolerance;           % 死去的分支（区间塌缩）被丢弃
end

两种 判决约定是整个研究最重要的分类：

  • monotonic CBW / BWA / SBW / BWAR：每级只把“命中阈值”一侧的区间前推，另一侧保持。分支 0 永远不会死。
  • fullstep Current：每级把区间向两侧对称的 ±w 分开（二分搜索式），两侧都可能死。

研究的关键结论之一正源于此：Current 的 fullstep 在主位二进制减半链上不允许插入任何冗余位（分裂健康递推 M(k+1)=min(w_k, H_k−w_k)），而单调族的端节点“哑金（end-gold）”噪声是全局量、无法用固定判决域消除——这决定了冗余只能加在单调架构（BWA→BWAR）上。

sar_convert.m 是独立的逐点直接转换，专门用来交叉验证区间算法（在测试 test_ideal_16bit_binary 等中做一致性门）。

2.5 指标与失败哨兵（adc_metrics.m）

width = accumarray(code+1, (hi-lo)', [M 1]);   % 每个码占据的输入区间宽度
missing = sum(width <= widthTolerance);          % 缺码 = 区间塌缩到 0
down = sum(diff(code) < 0); monotonic = (down==0);
if monotonic
    INL/DNL = endpoint-fit;                       % 端点拟合 LSB
else
    dm = Inf; im = Inf;                            % 非单调 → 失败哨兵 Inf
end

关键设计：非单调传输的 DNL/INL 一律置 Inf（传统按码排序的 T[k] 对非单调函数无效），这样失败芯片不会污染 统计、也不会被当成“好芯片”选中。m 行向量为 [DNL_max, INL_max, missing, monotonic, pass, diagDNL, regions, down]。

2.6 Monte Carlo 总装（run_mc.m / main_run.m）

evaluate_die 串起一条芯片的完整链路：architecture_definition → realize → transfer_tree → adc_metrics， 分别用 code0（CAL0，名义权重解码）和 code1（CAL1，真实权重解码）评估。run_mc 用 parfor（Threads 并行，可回退串行）跑 n 颗芯片。main_run 是 Phase 0–3 一键入口：先跑硬门测试 （理想二进制、CAL0 静态回归），再跑名义四架构，再跑 1k/10k MC，最后用 make_figures_svg 出图、写报告。

数据列约定（贯穿三项目）：每个 MC 矩阵是 n×16 行，前 8 列为 CAL0 指标、后 8 列为 CAL1 指标， 列顺序即 adc_metrics 的 m。因此 data(:,5)=CAL0 达标率、data(:,13)=CAL1 达标率、 data(:,9)=CAL1 DNL99 所用列、data(:,11)=零缺码判据。后续所有 *_mc_impl / run_variant_mc 都复用同一约定。

三、Phase 4–8 的扩展：广义引擎、冗余变体与选型

Phase 4–8 在不改动核心引擎的前提下，新增了“变体”层与“有限字长校准 / 动态”层。最关键的扩展是把 architecture_definition 泛化成 variant_definition，把 transfer_tree 泛化成 transfer_tree_gen，二者都复用 network_weights 与 adc_metrics。

3.1 广义变体定义（variant_definition.m）

新增三个变体：

  • CurrentR：Current 拓扑但 r 电容可调到 0，并支持 domMatch（域收缩到 ±2·w(MSB)）和 retune（按实际段总电容重算桥 Cb1/Cb2 使衰减比精确为 1/16、1/32）。
  • BWAR：BWA + topR（TOP 节点冗余帽）+ lowR1（LOW 节点冗余，需同步重调桥，见下）+ botCap（LSB 端赋权）。 这是最终推荐的架构。

它用 network_weights 解出有效权重后，按权重降序决定判决顺序 decIdx（哑端永远不判决）。

桥重调公式（LOW 节点加电容的硬约束）：分压器把 LOW 有效总权钉在 ≈Cb，单纯加 lowR1 会被“吸收”。 必须重调桥：Leff = L/256，Cb = Leff·L/(L−Leff)，其中 L = 256 + lowR1 + botCap。 这是 BWAR 能成立的关键技巧，也是后续 bwar 把它收敛为整数桥的起点。

3.2 广义判决树（transfer_tree_gen.m）

相比 Phase 0–3 的 transfer_tree，它做了三件事：

  1. 支持两种约定（fullstep / monotonic）统一在一个函数内，并通过 opt.offset（比较器 offset）、 opt.wScale（settling 缩放）、opt.decoderW（CAL1/CAL2 解码权重）扩展。
  2. 逐层记录 t.margin（判决裕度 M_k）、t.death（该级死去的分支数）、t.alive（存活节点数）—— 这是 Phase 5 诊断与 Phase 7 动态分析的量化基础。
  3. code1 改成“由决策比特 + 解码权重重建”（bitunpack → 累加），与 CAL0 的名义累加解耦，为 CAL2 有限字长铺路。

3.3 设计搜索与选型（design_search.m / main_phase48.m）

Phase 5 的 design_search 是两阶段网格搜索：先名义门（CAL1 零缺码+单调+规格），再过门候选按 “最坏层裕度”排序挑最优。验证后确认 BWAR-final = topR=10Cu@TOP + lowR1=240Cu@LOW（桥重调）+ botCap=1Cu， 19 判决，229.18 pF，在 CAL1（oracle 完美位权）下 100%/1000 颗通过（DNL99=0.980、INL99=0.569、零缺码、单调 100%）。

Phase 4（cal2_eval）扫描 CAL2 有限字长校准：要求绝对估计误差 <0.01 LSB16、相对 <10 ppm、系数字长 ≥24 bit。 Phase 6 跑 10k 决赛 MC（Finalists：BWAR-final + CurrentR-Z），Phase 7（dynamics_eval）用 offset 精确树平移、 settling 一阶统一系数、noise 采样统计传输三种模型做动态敏感性，Phase 8 按任务书权重评分 → BWAR-final 唯一过线。

四、Phase A/B/C 精炼：把非整数桥收敛到整数桥

Phase 4–8 推荐的 BWAR-final 有一个版图难题：桥电容 Cb = 1.949020 Cu = 292.35 fF 是非整数个单位电容， 实际电容器阵列只能做整数个单位电容的倍数。bwar 阶段回答的问题是：能否用整数 Cu 的桥（即 Cb=1/2/3 Cu）替代， 仍满足 16-bit 规格？ 它同样只读复用前两阶段的引擎。

4.1 显式桥构造器（bwar_build.m）

这是 bwar 自带的“BWAR 构建器”，与 p4_8 的 variant_definition('BWAR',…) 契约一致：

if p.Cb_Cu > 0
    a.bridge = p.Cb_Cu;                       % 显式整数桥
else
    Leff = L/256; a.bridge = Leff*L/(L-Leff); % Cb<0 → 复现 BWAR-final 的 1.949020 Cu
end

test_reference_bwar_final.m 正是用 bwar_build(cfg.ref)（Cb<0）复算 p4_8 的 BWAR-final， 断言电容表 / 桥 / 判决顺序完全一致，并复现 100%/0.980/0.569——用回归测试把三阶段锁死在同一物理模型上。

4.2 整数桥搜索（integer_bridge_search.m / fine_search.m）

这是本阶段的计算主体，采用分阶段（staged）Monte Carlo 漏斗控制成本：

结论（写入 final_report.md）：Cb=2 Cu（300 fF）可行——粗搜 4125 候选中 197 个过名义门、46 个 ≥99% 良率； 10k MC 最优达 100% 通过，DNL99 约 0.93–0.94（甚至略优于 reference 的 0.980）。Cb=1 最高仅 29.7%，Cb=3 名义门全灭。 因此非整数桥可安全收敛为整数桥 Cb=2Cu，消除版图实现障碍。

4.3 实际校准行为模型（Phase B/C）

  • practical_cal2.m：前台“平均式”位权校准——What = Wreal + noise + Vos_cal，noise~N(0,σ²) 多次平均后 经验验证 σ_cal ≈ σ_meas/√Navg；并单独研究系统性 offset（不随平均消失）。
  • coeff_encoding_eval.m：对比两种系数编码——FULL-WEIGHT（全权重量化）vs ERROR-ONLY（只量化 dW=What−Wnom 的差值，解码时还原）。ERROR-ONLY 用更小字长即可达 ≥99%（实测 dW|max|≈11 LSB，±256 LSB 范围内约 12 bit）。
  • offset_residual_eval.m：前台 offset 校准后的残余比较器 offset 对规格的影响（Phase C）。

六、关键算法如何实现（物理层面）

6.1 失配 → 权重（节点方程 + √面积律）

每颗芯片：物理电容按 σ_u·√cap 抖动 → 对每侧调用 network_weights 解节点方程得有效权重 → 两侧取平均。σ_u 由工艺常数 K_fF 与单位电容 Cu 决定，cfg.sigma = √(K/Cu) ≈ 1.6326%。这是所有统计的“物理墙”。

6.2 模拟 SAR → 数字区间（精确判决树）

不用“给电压、跑比较器”的黑箱，而是区间精确传播：根区间 = 输入域，每级按约定把存活区间一分为二， 记录决策比特、最终状态 state、名义累加 dc。叶子区间宽度之和守恒（断言 sum(hi−lo)=diff(domain)）， 塌缩到 0 的区间即“缺码”。state 直接给 CAL1（真实权重解码）的码，dc 给 CAL0（名义权重解码）的码。

6.3 三级校准（CAL0 / CAL1 / CAL2）

级别解码权重物理含义在本项目中的角色
CAL0名义（设计）权重不做任何校准基准，四架构原始 DNL/INL（大量非单调/缺码）
CAL1真实权重（oracle）假设能完美测出每个电容的真实值架构“可达性”上界；BWAR-final 在此 100% 达标
CAL2有限字长估计权重实际前台校准：带测量噪声 + 字长量化 + 编码Phase 4 扫描字长/误差；bwar Phase B/C 行为建模

6.4 裕度与“结构性无解”的判定

Phase 5 用 transfer_tree_gen 记录的逐层 margin M_k（最差存活节点到区间边界的距离 − 即将迈出的步长）量化脆弱性：

  • Current 的 fullstep：M(k+1)=min(w_k, H_k−w_k)，主位二进制减半链上任何 r 冗余位插入都破坏链条 → CurrentR-A（调顺序）与 -B（调 r 值）被结构性否定；去 r 帽的 CurrentR-Z 名义完美但失配下 M2/M3 层裕度被 TOP 段路径噪声（σ≈94 LSB16）压倒 → CAL1 良率 0%。
  • 单调族（BWA/BWAR）的端节点“哑金”噪声是全局量（σ_E≈67 LSB16），每层裕度都含它 → 必须用多点冗余（topR + lowR1 + botCap）且 LOW 加电容时同步重调桥才能压住。

这两条是整篇研究“为什么最终选 BWAR-final、为什么 Current 在授权内无解”的定量根据。

七、最终结论与代码演进价值

一句话：在 σ_u≈1.63% 的单位电容失配下，四种原始 16-bit CDAC 架构都无法靠 CAL1 达到 16-bit 规格； 通过给 BWA 桥结构叠加多点冗余（topR=10Cu / lowR1=240Cu 桥重调 / botCap=1Cu，19 判决，229.18 pF）得到的 BWAR-final 是唯一达标者（100%/1000，DNL99=0.980，INL99=0.569）。 bwar 阶段进一步证明该方案可收敛到整数桥 Cb=2Cu（300 fF），消除版图实现障碍，并保持 ≥99% 良率、DNL99≈0.93。
