一、图是怎么生成的？（为什么是 SVG）

工程刻意不依赖 MATLAB 图形后端 / 浏览器 / GPU，用两个纯文本 SVG 写出器把数据画成矢量图，好处是：可离线批量跑、文件小、能直接嵌进 Markdown 报告、任何人用浏览器都能看。

  • Phase 0–3 用 make_figures_svg.m（内置 bars 柱状 / linesvg 折线），输出到 calibration_architecture_study/figures/。
  • Phase 4–8 用更通用的 svgfig.m（折线/散点/虚线，支持 logy 坐标），输出到 calibration_architecture_study_p4_8/figures/；其中 01–04 也复用 Phase 0–3 逻辑。
  • Phase A/B/C 复用同一套 svgfig.m（bwar 把它 addpath 进来），在 finalize_impl_report.m 里输出 bwar_implementation_refinement/figures/Fig1~11。

注：reruns/20261018_202107/figures/ 和 .comment_backup/ 里是可复现重跑的副本，内容同源，不计入"新图"。_smoke.svg 是探针/冒烟测试的产物，属测试残留。

三、按"用途"重新归类（理解整体叙事）

诊断类 01_DNL/INL_P99、03/04/05 良率、07 可达区间、08 静态回归、12 裕度剖面、representative 曲线。作用：判定"谁达标、谁死、为什么死"。

校准精度类 05–08（p4_8 的 coeff_bits / cal_error 四张）、Fig9（bwar bits）。作用：定 CAL2 有限字长与权重估计误差的真实下界。

选型权衡类 06 电容、09/10 电容-vs-指标、11 复杂度、Fig1–5/11。作用：在"性能↔面积↔复杂度"三角里选最优并实现收敛。

验证类 Fig6–8（平均律/噪声）、Fig10（offset 鲁棒）。作用：证明推荐方案在真实非理想条件下仍稳。

代表芯片类 representative_*（Phase0-3）、13_BWAR_representative_INL。作用：把统计数字落到"具体某颗芯片的曲线"，让人信服最坏情况也 OK。

四、这些图合起来"讲了一个什么故事"

整套图的叙事是层层递进的"否证 + 收敛"：

  1. 先否证：Phase 0–3 的诊断图（01–05、07、representative）证明四种原始架构在 σ_u≈1.63% 失配下全都不达标——非单调架构连 INL 都无定义（05/07），单调架构 DNL 超标。
  2. 再找可行点：Phase 4–8 的冗余变体 + 现实校准图（01–04 达标率、05–08 精度预算、09–11 权衡、13 代表曲线）筛出唯一达标者 BWAR-final（229pF，100% 良率，DNL99=0.98）。
  3. 最后收敛到可版图实现：Phase A/B/C 的 Fig1–5/11 把非整数桥 1.949Cu 收敛到整数桥 Cb=2Cu，Fig6–10 验证平均/噪声/offset 鲁棒性，结论：整数桥版仍 ≥99% 良率、DNL99≈0.93，消除版图障碍。

每张图都不是装饰：横轴是"设计自变量"（电容、位宽、误差、Cb、Navg…），纵轴是"规格判据"（DNL/INL/良率），红线/虚线就是 16-bit 规格门槛。读图 = 读"离门槛还有多远"。

五、怎么自己看这些图

所有图都是纯 SVG 文件，直接用浏览器打开即可（无需 MATLAB）。路径：

  • calibration_architecture_study/figures/*.svg
  • calibration_architecture_study_p4_8/figures/*.svg
  • bwar_implementation_refinement/figures/Fig*.svg

生成逻辑在源码里：make_figures_svg.m（地基）、svgfig.m + write_phase4_outputs.m + main_phase48.m（Phase4–8）、finalize_impl_report.m（bwar）。已加中文注释，可对照阅读。
